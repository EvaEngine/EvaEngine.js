# EvaEngine.js TypeScript 完全重写方案

## 总体决策（已确认）
- **忠实 1:1 移植**：49 个 src 文件（~6.5k 行）+ 33 个测试文件（~2.2k 行）逐文件转 TS，public API、依赖（含版本）、行为全部不变，现有测试断言原样保留并全部通过。
- **发布形态**：src 写 TS，`tsc` 编译到 `dist/` 并生成 `.d.ts`，`package.json` 指向 dist；开发态测试仍直接跑 src 源码（tsx loader），日常无构建负担。
- 分支 `typescript`（自 main 切出），按层级分 commit 落在本地分支，**不 push、不 release**（Conventional Commits，pre-commit lint 继续生效）。

## 关键事实（已核实）
- 异常错误码分组号硬编码 `'11111'`（`src/exceptions/index.js:59`），不依赖物理路径；`template/`、swagger 的 `import.meta.dirname` 相对路径在 dist 镜像 src 目录深度时不变 → src→dist 迁移不破坏错误码与资源定位。类名不被压缩，`constructor.name` 稳定。
- 无类型依赖需手写 ambient 声明：`constitute`、`cloud-config-client`、`continuation-local-storage`、`doctrine`、`jwt-simple`、`app-root-path`（其余按转换时核实，能靠 `@types/*` 或自带类型的用现成的）。
- `createRequire` 动态加载用户侧 `.cjs/.js`（config/entities/swagger）属于对外边界，保持动态行为，类型按 `unknown` 收敛后窄化，不伪造强类型。
- `test/_demo_project` 等用户侧 fixture 保持 `.cjs` 不动（它们模拟的就是消费方 CommonJS 配置）。

## 实施步骤

### Stage 0 — 工具链基建（src 仍为 JS，全绿后提交）
- 新增 devDependencies：`typescript`、`tsx`、`typescript-eslint`、`eslint-import-resolver-typescript`、`@types/node`（≥20.11 支持 `import.meta.filename`）、`@types/express`、`@types/sequelize`、`@types/winston`、`@types/morgan`、`@types/lodash`、`@types/node-mocks-http` 等（按需增减）。
- `tsconfig.json`（typecheck 用，覆盖 src+test+bin，noEmit）+ `tsconfig.build.json`（emit dist，rootDir src）：`strict`、`module/moduleResolution: nodenext`、`target: es2023`、`verbatimModuleSyntax`、`isolatedModules`、`declaration`+`declarationMap`+`sourceMap`。相对导入沿用显式扩展名风格（NodeNext 要求 `.js` 写法，tsx 会映射到 `.ts`）。
- `eslint.config.js` 切到 typescript-eslint（flat config），保留 import 插件与现有规则取向，ignore 加 `dist/`。
- `npm test` 改为 `node --import tsx --import ./test/bootstrap.js --test --test-concurrency=1 ...`（文件列表暂不变）。

### Stage 1–4 — 按依赖层级转换 src + 对应 test（每层跑 lint+test 全绿后 commit）
1. `utils/`（15 文件）+ `test/utils/*`（含被众多测试引用的 `src/utils/test.js`）。
2. `exceptions/` + `test/exceptions/*`，同时落地第一批 ambient 声明（app-root-path 等）。
3. `services/`（interface、env、config、logger、namespace、now、event_manager、redis、cache、http_client、rest_client、joi、jwt_token(_kong)、providers）+ `test/services/*`。
4. `middlewares/`、`commands/`、`entities/`、`swagger/`、`di.js`、`engine.js`、`config/`、`index.js→index.ts` + 其余测试（di/engine/error_handlers/index/entities/commands/middlewares/swagger）与 `test/bootstrap.ts`。
- 转换纪律：同名同结构同导出；语义性注释保留、纯重复类型的 `@param` 标签随类型落地移除；公共签名不放 `any`，动态边界用 `unknown`+窄化；Sequelize 模型不做深度泛型建模（务实类型）；`DI.get` 保留字符串键公共契约，为已知服务名加类型化 overload。

### Stage 5 — 发布形态切换
- `package.json`：`main/types/exports` 指向 `dist/index.js`+`dist/index.d.ts`；`bin` 保持 `./bin/engine`（改为瘦 shim，原 CLI 逻辑原样移入 `src/bin.ts`，行为不变）；`build` = `tsc -p tsconfig.build.json` + 拷贝 ambient `.d.ts` 进 dist；`prestart` 用 tsx 跑 src。
- `.npmignore` 白名单 `src/**` → `dist/**`（template/bin/README 保持）。
- CI 不需大改（已有 build 步骤）；`npm pack --dry-run` 验证 tarball 内容。

### Stage 6 — 文档与收尾
- README（英文）：补充「 ships compiled JS + bundled TypeScript types，import 契约不变」，仓库开发段更新 build/test 说明。
- `docs/`：`development/commands.md`、`setup.md`（移除「无转译构建」表述）、`testing.md`（tsx）、涉及 src 文件名的组件文档按需小修。
- 全量验证：`npm run lint`、`npm run build`、`npm test`（需本地 Redis，若环境缺失将如实报告为未验证项）、`npm pack --dry-run`。
- 消费方冒烟验收：用打包出的 tarball 在临时 strict-TS ESM 项目里安装，验证 `import eva from 'evaengine'` 类型解析与运行期解构 core 对象（重点验证 ambient 类型随包发布的有效性）。

## 风险与对策
- **Sequelize/express 泛型深水区**：务实类型 + 集成边界收敛，不追求 ORM 全泛型化。
- **golden 快照**：`test/swagger/_example/docs.json` 必须逐字节不变（acorn/doctrine 解析行为未动，理论上稳定，测试兜底）。
- **类型随包发布**：ambient 声明通过 dist 内 `/// <reference path>` 引入；消费方冒烟测试验证，若工具链兼容不佳则回退为公共 API 不泄漏无类型依赖实例。
- `node-mocks-http` 在 dependencies 属既有问题，不在本次范围，不动。

## 验收标准
- 新分支上 lint / build / test 全绿，33 个测试文件行为断言不变全通过。
- tarball 含 dist+template+bin、不含 src；临时消费方项目 strict TS 冒烟通过。
- README 与 docs 与实际一致；交付报告含各 commit 摘要、验证证据与未验证项。
